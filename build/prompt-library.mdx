## Build a paid-social landing page

```text
Build a landing page for [PRODUCT] for [AUDIENCE] arriving from [CHANNEL / AD].
Use the attached ad for the campaign angle and the attached product for real product information.

The hero should continue the ad's message, make the product clear, and use one primary CTA.
Below it, include the education, proof, purchase section, and FAQ needed for this audience.

Use AI Knowledge for approved brand voice and claims.
Do not invent reviews, claims, discounts, pricing, or urgency.
Prioritize mobile.
```

## Build from a screenshot / URL

```text
Use [REFERENCE] for [LAYOUT / INTERACTION / STYLE] only.

Use our brand, connected product, approved copy, images, reviews, and offer.
Do not copy the reference brand's logo, claims, testimonials, pricing, product data, or imagery.
Keep the result editable in Jurni.
```

## Build from Figma

```text
Desktop frame: [FIGMA DESKTOP]

These are responsive versions of the same page.
Follow the visual structure while keeping text, media, buttons, and shopper controls editable.
```

## Edit one section only

```text
Change only the selected [SECTION].
Problem: [PROBLEM].
Desired result: [RESULT].

Keep [COPY / IMAGE / CTA / BEHAVIOR] unchanged.
Do not change other sections, products, purchase behavior, or publishing settings.
```

## Fix mobile only

```text
Mobile only — edit the selected section.

Fix:
- [PROBLEM 1]
- [PROBLEM 2]

Desired mobile order / hierarchy:
[ORDER]

Keep desktop, copy, CTA action, product choices, and all other sections unchanged.
No horizontal overflow.
```

## Restyle a purchase section without breaking it

```text
Restyle the selected purchase section to match [REFERENCE / DIRECTION].

Keep functional and unchanged:
- connected product;
- variants;
- selling plans / subscription choices;
- quantities;
- real pricing / offer behavior;
- current cart / checkout action.

Do not replace working controls with static design elements.
Do not invent discounts or purchase plans.
```

## Ask for a CRO audit before making changes

```text
Do not edit yet.
Audit this page for [AUDIENCE] from [TRAFFIC SOURCE].

For every recommendation label it:
- PAGE OBSERVATION
- HYPOTHESIS
- DATA NEEDED

Prioritize the 5 highest-leverage issues.
Do not invent performance data or customer research.
```

## Create a controlled experiment variant

```text
This is an A/B-test variant.
Change only [HYPOTHESIS].

Keep identical to control:
- product / purchase behavior;
- offer / price;
- non-target sections;
- CTA destination;
- tracking;
- responsive behavior unless it is part of the hypothesis.

After editing, summarize every difference from control.
```

## Communicate a real GWP offer

```text
Update this page for the approved gift-with-purchase campaign.

Qualification: [RULE]
Gift: [GIFT]
Limit: [LIMIT]

Explain the offer clearly near the campaign / purchase decision.
Keep the real product and purchase behavior unchanged.
Do not claim the gift is free unless the real Shopify setup makes it free.
Do not invent a different threshold or scarcity.
```

## Final pre-launch review

```text
Do not change anything yet.
Review this page for launch readiness.

Check visible page issues:
- message match;
- claims / proof;
- mobile layout;
- CTA consistency;
- product / offer presentation;
- placeholders / duplicated content.

Then create a separate LIVE QA checklist for:
- cart / checkout;
- actual product / variant / selling plan;
- offer / gift / shipping;
- forms / reviews;
- tracking / consent;
- Smart Link / campaign parameters.

Do not mark live checks as passed unless they were actually verified.
```
