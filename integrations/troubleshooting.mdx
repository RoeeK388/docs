Use this page when the integration looks connected in Jurni but **the thing you expected is not happening**.

Start with the symptom below. You do not need to understand how the provider's script is implemented before you can do the useful first checks.

## My review widget is empty or missing

Check these in order:

1. Open **Settings → Integrations** and confirm the correct review provider is enabled for this Jurni shop.
2. Open the provider's guide and confirm you saved the exact account value it asks for.
3. Check the page itself: did you actually add the provider's review section / widget?
4. If the widget is product-specific, confirm it points to the same real product / SKU / product ID the review provider uses.
5. Confirm the provider has **published** reviews for that product / group.
6. Test the real published page, not only the editor canvas.

Common provider-specific misses:

- **Yotpo** — App Key connects the account; the page widget also needs its Instance ID.
- **Trustpilot** — Business Unit ID identifies the business; the page widget also needs the correct Template ID.
- **REVIEWS.io** — the product SKU in the widget must match the SKU in REVIEWS.io.
- **Judge.me** — Jurni-hosted pages need the provider's compatible external / platform-independent widget setup.

[Review-provider setup →](/integrations/review-integrations)

### It works on my normal Shopify PDP but not on the Jurni page

That usually means the normal Shopify theme is doing work the Jurni-hosted page does not inherit automatically, or the product mapping differs.

If this is a **Shopify Page**, test the final `/pages/` URL and check whether the theme already loads the review app.

If this is a **Jurni-hosted page**, use the Jurni provider integration / widget rather than assuming the theme's app block will appear there.

## My Meta / GA4 / TikTok / GTM tracking is missing

Check:

1. Did you enter the correct ID for the correct brand account?
2. Are you testing a **published page** rather than only Preview?
3. Did you accept / trigger the expected consent state?
4. Did the shopper action actually happen?
5. Is the same tag installed through a different path instead?

Then verify in the provider:

- Meta → Test Events / your approved pixel debugging workflow;
- GA4 → Realtime / your analytics debugging workflow;
- GTM → Preview / Tag Assistant;
- TikTok → Events Manager / provider tools.

A Jurni field being saved does not prove an event arrived in the third-party account.

## My tracking fires twice

The most common cause is **two installation paths**.

Check whether the same tag / container loads through more than one of:

- Jurni native integration;
- Google Tag Manager;
- Custom Scripts;
- Shopify theme / app;
- another tracking app.

Do not keep adding another pixel to “fix” duplicates.

[Fix duplicate tracking →](/troubleshooting/duplicate-tracking-events)

## My Klaviyo form is a placeholder / empty

For an embedded Klaviyo form, there are two separate pieces:

1. the shop-level Klaviyo connection;
2. the **Form ID** for the exact embedded form on the page.

If the Company ID / Site ID is connected but the page form has no Form ID, the account can be connected while the form itself is still not configured.

[Connect Klaviyo forms →](/integrations/klaviyo)

## My Klaviyo / Postscript / Alia pop-up isn't showing

Check:

- provider is connected in the correct Jurni shop;
- the experience's pop-up controls allow that provider;
- the provider's campaign / display rules are active;
- the test visitor is actually eligible;
- consent is not preventing the script / campaign;
- the same provider is not installed separately through the Shopify theme or another loader.

A pop-up not appearing on every refresh does not automatically mean it is broken—the provider can use timing, targeting, previous visitor behavior, and frequency rules.

[Page pop-up controls →](/build/page-popups)

## My signup works visually but the subscriber isn't where I expected

The page render and the provider destination are different checks.

For Klaviyo / Postscript:

1. submit the **published** form using test data you control;
2. confirm the subscriber / opt-in in the provider;
3. confirm it entered the intended list / keyword / follow-up workflow;
4. check consent and provider-side eligibility.

Changing Jurni button styling will not fix a form that points to the wrong provider configuration.

## My integration works on Jurni-hosted pages but not Shopify Pages

A native Shopify Page runs in the **Shopify theme environment**.

Ask:

- Does the Shopify theme already install the tool?
- Is the tool being loaded twice?
- Does the provider expect normal Shopify product-page markup that is not present inside the Jurni section?
- Is there a Shopify Pages-specific compatibility / setup requirement?

Test the real `/pages/` destination, not just the Jurni preview.

[Shopify Pages limitations →](/shopify-pages/limitations)

## My integration works on Shopify but not a headless / non-Shopify storefront

A Shopify product ID, theme script, or checkout event path does not automatically map to another storefront architecture.

Confirm with the Jurni team:

- which product / SKU identifier the provider expects;
- where the tool loads;
- how cart / checkout events are sent;
- whether purchase attribution is connected;
- whether browser / server-side pieces are both required.

Do not paste Shopify-specific setup into a custom storefront and assume it should work unchanged.

## Shopify Analytics is missing

For Jurni's Shopify Analytics setup on the supported Jurni-hosted flow, confirm:

- the Shopify Headless storefront / channel used for the setup still exists;
- the **public** Storefront API token is current;
- it belongs to the same Shopify store as the Jurni shop;
- you are comparing the intended dates / timezone.

[Shopify Analytics setup →](/getting-started/shopify-analytics)

## A Custom Script isn't running

First check the marketer-facing settings:

- script is enabled;
- page targeting includes the page you are testing;
- you are testing the real published environment;
- consent allows the script to run when applicable.

Tracking Custom Scripts are intentionally not a reliable thing to test only in editor Preview.

If those are correct and the script still fails, send the script owner / Jurni team the browser error or exact vendor requirement rather than debugging production JavaScript by trial and error.

[Custom Scripts →](/integrations/custom-scripts)

## A connection saves, but data still doesn't arrive

A saved connection proves only that the setting was accepted.

The complete flow can still depend on:

- page placement;
- product mapping;
- visitor consent;
- provider-side campaign status;
- checkout / downstream integration;
- account permissions;
- external platform processing.

Verify the final outcome in the provider that owns it.

## What to send Jurni Support

If the issue remains, send enough information to reproduce **the customer outcome**, not only the settings screen:

- integration name;
- Jurni shop / brand;
- exact page URL;
- publishing method: Jurni-hosted or Shopify Pages / other;
- expected behavior;
- actual behavior;
- affected product / form / widget if relevant;
- screenshot / recording;
- whether it works on the normal store;
- whether consent was accepted;
- provider error / test-event evidence if you have it.

Do **not** paste private API secrets into Slack screenshots or AI prompts.
