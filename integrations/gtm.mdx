Google Tag Manager (GTM) lets your team use Jurni events as inputs for analytics and marketing tags without hard-coding every vendor directly into each experience.

## Before you add GTM

First decide **where GTM is already installed**.

A Jurni experience can be served from a Jurni/custom subdomain or published inside Shopify Pages. If your Shopify theme already loads the same GTM container, adding that container again through Jurni on the Shopify Page can cause tags and pixels to fire twice.

<Warning>
  Do not load the same GTM container twice on one page. Duplicate containers can produce duplicate PageView, conversion, and advertising events.
</Warning>

## Connect GTM to Jurni

<Info>
  Connecting the GTM container and forwarding Jurni browser events are separate steps. Adding the container ID loads GTM, but it does not automatically push every Jurni interaction into `dataLayer`.
</Info>

<Steps>
  <Step title="Find your GTM container ID">
    In Google Tag Manager, copy the container ID for the container you want to use.
  </Step>
  <Step title="Open Jurni tracking or integration settings">
    Add the GTM container using the Google Tag Manager integration or the supported tracking configuration in your workspace.
  </Step>
  <Step title="Choose where it should load">
    If your Jurni setup supports page-level targeting, include only the pages that need Jurni to load GTM.
  </Step>
  <Step title="Publish and test">
    Open the live page and use GTM Preview / Tag Assistant to confirm the container appears once and receives the expected events.
  </Step>
</Steps>

## Jurni browser events

Jurni's current storefront event model exposes browser events that can be bridged into GTM, including:

- `jurni:page-view`
- `jurni:button-clicked`
- `jurni:add-to-cart`
- `jurni:add-to-cart-complete`
- `jurni:open-cart`
- `jurni:open-product-page`
- `jurni:goto-external-url`
- `jurni:scroll-to-section`
- `jurni:go-to-checkout`
- `jurni:play-video`
- `jurni:video-watched`
- `jurni:session-engaged`

If your GTM implementation needs these interactions, use a Jurni Event Bridge or custom mapping through **Settings → Custom Scripts** to forward the selected browser events into `dataLayer`.

<Tip>
  For add-to-cart conversion tags, prefer `jurni:add-to-cart-complete` when you need confirmation that the cart action completed successfully rather than only recording the initial add-to-cart attempt.
</Tip>

Use the Event Dictionary for the product-level meaning of Jurni's reporting events and the payload fields available to downstream tracking.

## CTA tracking

For click reporting, clear CTA metadata makes downstream GTM events much easier to use. Prefer names that describe the shopper action, such as **Hero Add to Cart**, **Start Quiz**, or **Checkout**, rather than generic labels such as **Button**.

## Jurni subdomain vs. Shopify Pages

A common implementation is:

- Load GTM through Jurni on Jurni-hosted/subdomain experiences.
- Let the Shopify theme load GTM on Shopify Pages when the same container is already installed there.

If your account has both page types, use script/page targeting so the container is not injected twice.

## Debugging

When a GTM event is missing or duplicated:

1. Check whether the container loads once or multiple times.
2. Confirm the page is included in the Jurni tracking configuration.
3. Verify consent tools are not blocking the tag.
4. Use GTM Preview to inspect the event stream.
5. Confirm the underlying Jurni event actually occurred—for example, verify the product reached cart for AddToCart.
6. Check whether a second implementation exists in the Shopify theme, custom scripts, or another tag manager.
