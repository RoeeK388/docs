Use this guide when the page looks right but the **wrong thing happens after the shopper chooses a product or clicks the purchase button**.

Start with the actual cart / checkout result. That tells you which part of the purchase setup is wrong.

## Nothing is added to cart

Check:

1. Is the product / variant still active and available in Shopify / your commerce system?
2. Is the page using the intended purchase action?
3. If this is a Shopify Page, is its theme / cart connection configured?
4. Does the same product work from another page / normal storefront?
5. Is a third-party cart app or custom storefront integration involved?

For native Shopify Pages, see [Cart connection](/shopify-pages/cart-config).

For non-Shopify / headless stores, confirm the agreed [purchase integration](/commerce/non-shopify-purchase-flows).

## The wrong product is added

Compare:

- product shown on the page;
- selected product in the purchasing section;
- product that appears in cart.

A product title typed into a heading does not control the cart item. The purchasing section needs to be connected to the intended real product.

If the page was duplicated from another campaign, recheck the product connection rather than assuming the visible copy was the only thing that carried over.

## The wrong variant is added

Check the exact option the shopper selected and the variant that reached cart.

If Shopify variants were changed, removed, or recreated after the page was built, reopen the page and retest the important combinations.

Two variants with similar labels are still different commerce items.

## Subscription is missing or becomes one-time purchase

If one-time works but subscription does not:

1. Confirm the product still has an active selling plan in Shopify / your subscription app.
2. Confirm the relevant product / variant is included in that plan.
3. On the page, choose the actual subscription option / selling plan.
4. Add to cart / checkout and inspect the line item.

A visible “Subscribe & Save” label does not create a subscription plan.

[Subscriptions & selling plans →](/building-funnels/subscriptions-selling-plans)

## The wrong subscription frequency / plan is added

Check which selling plan is selected—not only whether “Subscription” is selected.

If the product has several frequencies, test each high-priority plan through cart / checkout.

Page copy such as “Ships every 30 days” should match the plan the customer actually selected.

## The quantity is wrong

Confirm whether the page uses:

- a fixed quantity;
- a quantity selector;
- multi-product / bundle logic;
- an offer that changes gift quantity.

Renaming a card “3-pack” does not itself make the purchase quantity three.

Test the real cart lines / quantities instead of reading the visual pack label as proof.

## Bundle items are wrong

For a bundle / multi-product journey, test more than one valid combination.

Verify:

- expected products;
- variants;
- quantities;
- purchase type;
- final cart lines;
- actual discount / bundle pricing.

The page can show the intended bundle design while the underlying commerce flow still needs correction.

## Gift appears but costs money

This is usually an **offer / Shopify discount** problem rather than a failure to add the gift.

Jurni can qualify / add the supported gift while Shopify / the discount system controls whether that gift is actually free.

Check:

- gift product / variant;
- qualifying rule;
- Shopify gift price / discount;
- final checkout amount.

[Gift with Purchase →](/building-funnels/gift-with-purchase)

## Discount code is shown but checkout rejects it

Check the code in Shopify:

- exact code spelling;
- active dates;
- eligible products;
- customer eligibility;
- minimum purchase;
- one-time vs subscription eligibility;
- combination rules;
- usage limits.

Jurni displaying the promotion does not override Shopify's code rules.

[Discount-code offers →](/commerce/discount-code-offers)

## Free shipping is shown but checkout charges shipping

Compare the Jurni campaign rule with the actual Shopify shipping eligibility:

- threshold / quantity;
- subscription condition;
- customer shipping address / market;
- products;
- active shipping discount / rate.

The page message and the checkout rule need to agree.

[Free-shipping offers →](/commerce/free-shipping-offers)

## Add to Cart works but the drawer doesn't open

The item can be added successfully while the intended **theme / cart-app UI** fails to open or refresh.

This is common when a Shopify Page needs a connection to the store's existing theme cart / Rebuy / cart app.

First inspect the actual cart contents. Then follow [Shopify Pages cart connection](/shopify-pages/cart-config) for the drawer behavior.

## It works in Preview but not on the live Shopify Page

Preview and native Shopify Pages are different environments.

On the `/pages/` URL, check:

- Shopify template / app block;
- theme / cart app;
- product / cart behavior;
- theme scripts;
- offer compatibility.

Use [Shopify Pages limitations](/shopify-pages/limitations) when the issue only appears in the theme environment.

## It works on Shopify but not on our headless / custom store

Do not troubleshoot a custom frontend as if it were a Shopify theme.

The Jurni team / your developer needs to confirm the intended:

- product / variant identifiers;
- cart API / checkout link;
- session / cart token behavior;
- subscription / offer mapping;
- purchase attribution.

[Headless & non-Shopify purchase paths →](/commerce/non-shopify-purchase-flows)

## A useful support report

If the issue remains, send:

- exact page URL;
- publishing method;
- expected product / variant / plan / quantity;
- what actually reached cart;
- screenshot / recording of the selection and cart;
- affected Shopify product link where relevant;
- whether the same purchase works on the normal store.

That is much more useful than “the Buy Box is broken.”
