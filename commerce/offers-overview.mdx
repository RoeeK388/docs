Use **Offers** when the campaign promise depends on a real promotion such as a gift, free shipping, samples, or a Shopify discount code.

For Shopify brands, think of every offer as two connected pieces:

1. **What Jurni shows / qualifies on the experience.**
2. **What Shopify actually charges or applies in cart / checkout.**

Those two pieces need to match before you send traffic.

## The most important rule

**A Jurni offer does not automatically create the underlying Shopify discount.**

Examples:

- “Spend $$75 and get a free gift” → Jurni can manage the supported qualification / gift flow, but Shopify still needs to make the gift $$0 or discounted as promised.
- “Free shipping over \$50” → Jurni can show the qualification, but Shopify still needs a matching shipping rate / discount for the shopper's address.
- “Use code SAVE15” → the code must already exist in Shopify with the correct product, customer, timing, purchase-type, and combination rules.
- “Choose two samples” → the samples can still have a price unless Shopify / product pricing makes them free.

The current **Create Shopify Discount** control shown on some offer forms is disabled. Saving an offer is not the same as creating its Shopify discount.

## A marketer offer workflow

<Steps>
  <Step title="Write the exact customer promise">
    Before configuring anything, state the offer in one sentence: **who / what qualifies, what the shopper receives, and any important limit or timing.**
  </Step>
  <Step title="Set the real Shopify rule">
    Configure or confirm the discount, shipping rate, gift price, or code in Shopify / your existing discount app. If another person owns Shopify discounts, align the rule with them first.
  </Step>
  <Step title="Create the matching Jurni offer">
    Open **Offers**, choose the supported type, set its qualification, scope, timing, products, and shopper-facing text where available.
  </Step>
  <Step title="Explain the offer on the page">
    Use clear campaign copy near the hero / purchase decision when the promotion matters to the campaign. The page message should match the actual offer rule exactly.
  </Step>
  <Step title="Test both qualifying and non-qualifying carts">
    Verify the real published experience, cart, and checkout. Remove a qualifying item or drop below a threshold and confirm the result updates correctly.
  </Step>
</Steps>

## Offer scope: where should it run?

Use **Global** when the offer should apply across eligible Jurni experiences in this shop.

Use the selected-experiences option when the promotion belongs only to specific campaigns / pages. The current UI may still use the legacy label **Funnels** for this control.

This scope applies to Jurni experiences—it is not a rule that automatically changes every Shopify store page.

## Timing

Use start / end timing only when the campaign truly has those dates. The shopper-facing page copy should use the same approved timing.

Do not add countdowns, “ending soon,” or urgency that is not represented by the actual campaign.

## How to test an offer properly

For every offer, test at least:

- a cart that **should not** qualify;
- the exact point where it **should** qualify;
- the intended product / variant / purchase type;
- removing / changing the qualifying item;
- final checkout price / shipping / gift;
- the market / currency if your campaign runs across markets.

For Shopify Pages or third-party theme carts, verify the offer in that actual cart environment. Do not assume the Jurni-hosted cart UI automatically appears in a native Shopify drawer.

## What Jurni does not currently provide here

The self-service offer picker currently focuses on:

- Gift with Purchase
- Free Shipping
- Samples
- Discount Code

Do not look for a general-purpose Shopify discount-function builder, arbitrary tiered-pricing engine, or full cart upsell designer in this area.

For a promotion outside these supported flows, confirm the actual Shopify / cart implementation with your team and use the landing page to communicate it accurately.
