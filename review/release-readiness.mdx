## Confirm before publishing the Buy Box guides

Check final entry points and labels in a demo shop. The reviewed implementation uses Create/Save and a separate Add Buy Box to page action; ENG-2983 requests a Save / Save and add to page split and template tabs. Do not publish the requested design as the implemented screen without checking it.

Verify AI is available after product/template setup, connected-page counts are presented clearly, shared edits update the expected uses, and native Shopify Pages follow the correct republishing process. Check the page-only variation workflow: managed Buy Boxes do not expose the ordinary Global Section Detach action in the reviewed panel.

Verify deletion behavior on existing references. The reviewed backend blocks deleting the last active Buy Box and changes the default when required, but deletion must not be documented as a page-unpublish or automatic replacement operation.

## Confirm before publishing confidence guidance

Verify the released success metrics, selectable confidence thresholds, minimum-data gates, and status labels. The available spec proposes configurable minimums of 500 sessions per compared arm for CVR/RPS and 500 sessions plus 30 orders per arm for AOV; do not treat these as universal statistical sufficiency or confirmed production defaults.

Verify Bayesian confidence is actually implemented, that it is not calculated as one minus a p-value, and that its underlying model supports the existing Orders/Sessions metric. Confirm Winning is a live state, Winner is a manual declared outcome, and no automatic stopping is implied.

Confirm behavior for negative/zero lift, zero control baseline, custom thresholds below 80%, missing values, multiple variants, and the actual end/traffic-routing controls. Keep calculation internals out of the marketer guide; describe only the observable result.

## Confirm before publishing engagement calculations

**Duration:** establish the start/end signals, active versus elapsed time, tab-hidden time, same-page returns, the requested 30-minute inactivity cutoff, and which measured visits are included in the average. Do not publish the proposed cutoff as shipped before verification.

**Scroll depth:** confirm whether the per-session measure is maximum depth or another value, how viewport height and changing page height are handled, and which sessions enter the average. Do not import GA4's scroll-event threshold.

**Bounce:** identify exactly which events qualify as interaction and how missing/no-consent data is treated. Confirm scrolling and time alone do or do not qualify. Do not substitute GA4's engaged-session definition.

**All three:** confirm reporting start date, historical backfill, zero versus missing display, experiment and experience coverage, aggregation, device breakdowns, and native Shopify Pages/headless support.

## Screenshot capture list

Use a demo shop with approved non-customer content. Capture the current AI composer and attachments, Guidance/Skills setup, the editor with mobile/desktop indicators, Buy Box product/template setup, the Buy Box Manage/shared-save warning, the updated experiment overview, confidence status, and engagement metrics with tooltips.

Crop around the control being explained. Remove private customer details, credentials, billing information, and irrelevant browser chrome. Use short descriptive filenames and alt text, plus captions when a screenshot depends on a rollout or version. A design mockup must be labeled as a mockup, never a live screen.

No platform screenshots were added in this pass: authenticated browser capture was unavailable and the supplied help-center PDFs contained no embedded screenshot images. Obtain current captures before the visual documentation pass.
