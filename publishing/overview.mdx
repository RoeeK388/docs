Publishing answers one simple question: **where should this campaign live when a customer clicks the link?**

Jurni supports more than one live destination. Choose the path based on the campaign and storefront—not because one URL format looks more “native.”

## Which publishing path should I use?

| If you want… | Start with… | Typical URL |
| --- | --- | --- |
| A fast Jurni-hosted campaign page with Jurni's standard runtime | **Jurni-hosted page** | `go.brand.com/offer` after a custom subdomain is connected |
| A Jurni-hosted page before a custom subdomain is connected on Shopify | **Shopify app-proxy route** | `brand.com/apps/jurni/offer` |
| The page to live inside the Shopify Online Store theme environment | **Shopify Pages** | `brand.com/pages/offer` |
| A headless / non-Shopify storefront | **Your agreed custom setup** | Your team's domain / route |

<Tip>
  For most campaign decisions, start with the environment the page actually needs—not the prettiest-looking URL. A Smart Link can give the campaign a stable branded entry URL separately.
</Tip>

## Jurni-hosted page

Use the Jurni-hosted path when the experience should run in Jurni's storefront environment.

For Shopify brands:

- before a custom Jurni subdomain is connected, the default route can use the Shopify app proxy;
- after a custom subdomain is connected, you can use branded Jurni URLs such as `go.brand.com/...`.

This is usually the simplest path for Jurni-hosted campaign experiences because the page uses the Jurni storefront, cart / integration setup, and tracking path configured for that shop.

[Set up a custom subdomain →](/getting-started/custom-subdomain)

## Shopify Pages

Use **Shopify Pages** when the experience specifically needs to live at a native Shopify `/pages/` URL and run inside the Shopify theme environment.

This can be useful when your team wants:

- a native Shopify Page URL;
- the store's theme header / footer or theme layout;
- Shopify theme / app scripts that belong to that environment.

But it is not simply the Jurni-hosted page with a different URL. The theme, cart, app scripts, and layout can behave differently.

Before moving a live campaign to Shopify Pages, check:

- [Shopify Pages setup](/shopify-pages/setup-publish)
- [Shopify Pages limitations](/shopify-pages/limitations)
- [Shopify Pages cart connection](/shopify-pages/cart-config)

## Headless and non-Shopify storefronts

If your store does not use Shopify Online Store as the frontend, use the publishing, cart, checkout, and tracking path agreed with the Jurni team.

A Shopify theme app block does not publish into a separate headless frontend. A WooCommerce, Salesforce, or custom storefront also does not automatically use Shopify Pages or the Jurni Shopify cart.

[Headless & non-Shopify setup →](/getting-started/choose-your-setup)

## Page URL vs. Smart Link

These are different jobs:

**Page URL** = where the experience itself is published.

**Smart Link** = the campaign-facing URL that decides where traffic should go.

Example:

- Your page lives at `go.brand.com/pages/summer-pdp`.
- Your campaign uses `go.brand.com/summer` as the Smart Link.
- That Smart Link can point to the page today and later become the entry point for an experiment without requiring you to edit every ad destination.

Use a [Smart Link](/building-funnels/smart-links) when you want campaign traffic managed centrally.

For experiments, the Smart Link connected to the test is the URL that should receive experiment traffic.

## A marketer launch flow

<Steps>
  <Step title="Finish and review the page">
    Check the copy, mobile / desktop layout, product or conversion path, and anything the page must preserve from the campaign brief.
  </Step>
  <Step title="Publish to the chosen environment">
    Use Jurni-hosted publishing, Shopify Pages, or your agreed headless/custom path. Do not treat Preview as the final live environment.
  </Step>
  <Step title="Create or choose the campaign link">
    Use a Smart Link when paid media, email, creators, QR codes, or experiments should have a stable entry URL you can manage in Jurni.
  </Step>
  <Step title="Test the exact URL you will use">
    Open the real campaign link and check the destination, purchase / conversion action, offer, integrations, tracking, consent, and mobile experience.
  </Step>
  <Step title="Launch and monitor">
    Once traffic is live, avoid casual changes to the page or routing that make campaign results harder to interpret.
  </Step>
</Steps>

## Which one should I choose?

**Choose Jurni-hosted** when you want the standard Jurni campaign runtime and do not specifically need Shopify's theme environment.

**Choose Shopify Pages** when the `/pages/` URL and theme / app environment are part of the requirement.

**Choose the custom/headless path** when your storefront architecture requires it.

If you are unsure because of a cart, consent, tracking, or theme dependency, test that dependency before changing a live campaign destination.
