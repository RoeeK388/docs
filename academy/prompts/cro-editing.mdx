Use these prompts when a page already exists and you want to make it clearer, more persuasive, or easier to use **without rebuilding everything**.

The strongest CRO prompts identify the problem, name the target area, protect the working parts, and separate visible observations from hypotheses.

## Audit the page before changing anything

```text
Do not edit yet.
Audit this page for [AUDIENCE] arriving from [TRAFFIC SOURCE].

Evaluate:
- message match with the campaign / ad;
- clarity of the first screen;
- product recognition;
- proof appearing at the right time;
- CTA consistency;
- unnecessary friction or repeated sections;
- mobile hierarchy;
- clarity of the purchase decision.

For every recommendation label it:
PAGE OBSERVATION — directly visible in the page
HYPOTHESIS — a testable interpretation
DATA NEEDED — something to confirm in analytics, customer research, cart, or checkout

Prioritize the top 5 issues.
Do not make changes yet.
Do not invent customer research or performance data.
```

## Optimize the hero / above the fold

```text
Edit only the selected hero.
Audience: [AUDIENCE].
Traffic source / message: [SOURCE / ANGLE].

The hero should answer quickly:
1. What is this?
2. Why should this visitor care?
3. Why should they trust it enough to continue?
4. What is the next action?

Change:
- headline to focus on [BENEFIT / ANGLE];
- supporting copy to a maximum of [X] lines;
- proof below the CTA using only [APPROVED SOURCE];
- hierarchy so the primary CTA is obvious.

Keep unchanged:
- product image / [ASSET];
- CTA action;
- product / purchase behavior;
- all sections below the hero.

Mobile: [MOBILE REQUIREMENTS].
Desktop: preserve [DESKTOP REQUIREMENTS].
```

## Improve message match from an ad

```text
Compare the attached ad with the current hero.
Do not edit yet.

List the specific mismatches in:
- headline promise;
- audience language;
- product emphasis;
- visual emphasis;
- offer;
- CTA expectation.

Then propose one revised hero direction that continues the ad's story without adding claims or promises that are not in the supplied sources.
Wait for approval before editing.
```

## Move proof earlier

```text
The page needs stronger credibility before asking the visitor to purchase.

Move / adapt only the approved proof from [SECTION / SOURCE] so a compact version appears [DIRECTLY BELOW HERO / ABOVE PURCHASE SECTION].

Use only existing real reviews, ratings, customer counts, press, certifications, or guarantee copy that are already supplied.
Do not invent new proof.
Keep the original detailed proof section unless I explicitly ask to remove it.
```

## Simplify a cluttered section

```text
Edit only the selected [SECTION].
The current issue is too many competing messages and visual elements.

Reduce it to:
- one section headline;
- one short supporting paragraph;
- the [3 / 4] most important items;
- one clear primary action if the section needs an action.

Remove repetition, decorative copy, and secondary elements that do not help the visitor understand [DECISION / BENEFIT].
Keep the factual meaning and all functional controls intact.
```

## Tighten long copy

```text
Rewrite only the selected copy for faster scanning on mobile.

Audience: [AUDIENCE].
Purpose of this section: [PURPOSE].

Keep:
- all approved facts;
- [MUST-KEEP CLAIM / PHRASE];
- the current tone.

Change:
- shorter sentences;
- shorter paragraphs;
- remove repeated ideas;
- put the most important point first;
- use bullets only where they improve scanning.

Do not add new claims, numbers, comparisons, reviews, or promises.
```

## Rewrite benefits around customer outcomes

```text
Rewrite the selected benefit section using only the approved product facts below.

Product facts:
[PASTE / ATTACH FACTS]

For each benefit:
1. Start with the customer-relevant outcome or use case.
2. Explain the product fact that supports it.
3. Keep the explanation to [LENGTH].

Do not exaggerate beyond the supplied facts.
Do not introduce health, performance, or comparative claims that are not approved.
```

## Reduce CTA competition

```text
Review all visible CTAs on this page.
Do not change them yet.

Primary customer action should be: [PRIMARY ACTION].

Identify:
- CTAs that support the same action;
- CTAs that compete with it;
- inconsistent labels for the same action;
- links that may distract before the purchase decision.

Then propose a simpler CTA hierarchy.
Preserve required navigation, legal links, and existing purchase behavior.
```

## Make CTA copy clearer

```text
Write 8 CTA label options for the selected action.

Action actually performed: [ADD TO CART / CHECKOUT / START QUIZ / VIEW PRODUCT / SIGN UP].
Audience: [AUDIENCE].
Tone: [TONE].

Requirements:
- clear about what happens next;
- maximum [X] words;
- no fake urgency;
- no discount wording unless the discount is real and approved.

Do not change the button behavior.
```

## Fix a mobile hero without changing desktop

```text
MOBILE ONLY — edit the selected hero.

Problems to fix:
- [IMAGE CROPS PRODUCT]
- [CTA TOO FAR BELOW FOLD]
- [TOO MUCH EMPTY SPACE]
- [TEXT TOO WIDE / DENSE]

Desired mobile hierarchy:
1. Headline
2. Short supporting copy
3. Primary CTA
4. Product image / proof in the order specified: [ORDER]

Keep desktop unchanged.
Keep all copy, product selection, CTA action, and commerce behavior unchanged unless explicitly listed above.
No horizontal overflow.
```

## Fix a mobile purchase section

```text
Edit the selected purchase section for mobile usability only.

Keep all real products, variants, selling plans, quantities, prices, and purchase behavior unchanged.

Improve:
- tap-target spacing;
- option readability;
- hierarchy between product choice and CTA;
- image sizing;
- vertical spacing;
- visibility of the selected option.

Do not simplify by removing a valid customer choice.
Do not replace functional selectors with static cards.
Keep desktop unchanged.
```

## Reorder a page around the decision journey

```text
Do not edit yet.
Map the current page sections to this visitor journey:
1. Understand the promise
2. Believe the promise
3. Understand the product / mechanism
4. See proof
5. Resolve objections
6. Make the purchase decision

Identify sections that are:
- out of sequence;
- repeated;
- missing a clear job;
- asking for a purchase before enough context is available.

Propose a revised section order using the existing content first.
Do not create new sections unless there is a specific gap that cannot be solved by reordering.
```

## Improve an FAQ

```text
Review the selected FAQ for [AUDIENCE].
The FAQ should resolve purchase objections, not repeat marketing copy.

Keep questions that address:
- product use / fit;
- purchase / subscription questions;
- shipping / returns where relevant;
- common objections supported by our approved information.

Remove or merge questions that repeat the same point.
Rewrite answers to be direct and easy to scan.
Do not invent policies or product claims.
```

## Make social proof more useful

```text
Use only the approved testimonials / reviews already supplied.

Select the [3 / 5] pieces of proof that best support this page's angle: [ANGLE].
Prioritize variety of objections / use cases instead of five versions of the same statement.

For the selected section:
- keep quotes verbatim unless I ask for an excerpt;
- preserve customer attribution;
- do not create ratings or review counts;
- improve layout for scanning on mobile.
```

## Create three alternative hero directions without editing

```text
Do not edit the page.
Create 3 distinct hero directions for the same product and audience.

Product: [PRODUCT]
Audience: [AUDIENCE]
Traffic source: [SOURCE]
Approved facts / claims: [SOURCE]

Direction A: lead with [BENEFIT]
Direction B: lead with [PROBLEM / PAIN]
Direction C: lead with [PROOF / DIFFERENTIATOR]

For each direction provide:
- headline;
- subhead;
- proof idea using supplied evidence;
- CTA label;
- why this is a meaningfully different hypothesis.

Do not invent facts or promise performance.
```

## Make the page feel more premium without vague styling

```text
Restyle only [SECTION / PAGE] toward a cleaner premium ecommerce aesthetic.

Use these concrete principles:
- more whitespace between major content groups;
- fewer competing font sizes;
- stronger hierarchy between headline, body, and supporting labels;
- restrained borders / dividers;
- larger product imagery where it improves product recognition;
- remove decorative elements that do not add information;
- preserve brand colors and typography from AI Knowledge.

Keep all copy, product data, links, and functional behavior unchanged unless specified.
```

## Recover from an over-edited section

```text
Stop making additional changes.

Correct parts to keep:
- [CORRECT PART 1]
- [CORRECT PART 2]

Problem introduced:
- [PROBLEM]

Fix only that problem.
Do not reinterpret the original brief or redesign the rest of the section.
Preserve product behavior, CTA action, mobile / desktop settings, and all other sections.
```

## Ask for the smallest useful next edit

```text
Do not change anything yet.
Given the current page and campaign brief, recommend the single highest-priority page edit we should make next.

Explain:
- the visible problem;
- the hypothesis;
- exactly what would change;
- what would stay fixed;
- which metric / behavior we would watch afterward.

Do not recommend a full-page redesign unless the current structure prevents a meaningful isolated improvement.
```
