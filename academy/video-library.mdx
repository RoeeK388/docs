# Jurni Academy video curriculum

Academy is designed to pair **short, focused walkthrough videos** with the written playbooks. The videos should show the real workflow in Jurni; the written lesson should remain complete enough to use without watching the video.

<Note>
  The lessons below are the recommended recording curriculum. Do not treat a lesson as published video content until an approved recording is embedded on the corresponding Academy page.
</Note>

## Recording principles

Keep most lessons between **3 and 8 minutes**. One video should answer one practical question.

A strong Jurni Academy video should:

- begin with the result the marketer is trying to achieve
- use a realistic demo campaign and product
- show the actual Jurni controls only when they matter to the workflow
- explain why a decision is being made, not narrate every click
- include the prompt on screen when AI is used
- show the resulting page, not only the AI response
- end with what to verify or test next

Avoid long feature tours. If a topic needs 20 minutes, divide it into several lessons.

## Learning path 1: first day in Jurni

### 1. The Jurni growth workflow

**Recommended length:** 4 minutes

**Outcome:** understand how campaign, experience, publishing, Smart Link, experiment, and analytics fit together.

**Demo outline:**
1. Start with a Meta ad and campaign objective.
2. Show the experience that continues the message.
3. Show its publishing destination.
4. Show the Smart Link used for campaign routing.
5. Show how that link can become an experiment entry point.
6. Show where results are read.

**Companion:** [Launch your first campaign](/academy/start/first-campaign)

### 2. Build your first page with AI

**Recommended length:** 6 minutes

**Outcome:** produce a useful first draft from a campaign brief instead of a generic “make a page” request.

**Demo outline:**
1. Create/open a new experience.
2. Attach the campaign ad and connected product.
3. Paste a structured prompt.
4. Review the generated page flow.
5. Make one focused hero correction.
6. Check mobile.

**Companion:** [Prompting 101](/academy/prompting-101)

### 3. Publish and test the campaign URL

**Recommended length:** 5 minutes

**Outcome:** understand the difference between the editor, published destination, and campaign URL.

**Demo outline:**
1. Save and preview.
2. Show publishing options relevant to the demo shop.
3. Publish.
4. Create/use a Smart Link.
5. Open the exact campaign URL on mobile.
6. Complete the primary CTA.

**Companion:** [First campaign](/academy/start/first-campaign)

## Learning path 2: Jurni AI masterclass

### 4. Prompting 101 in one real build

**Recommended length:** 8 minutes

**Outcome:** understand Context → Goal → Sources → Change → Keep → Behavior → Responsive → Verify.

**Demo outline:**
1. Show a vague prompt and explain why it creates guessing.
2. Add campaign context.
3. Attach a product and ad.
4. Add keep/behavior constraints.
5. Generate.
6. Make a correction prompt instead of rebuilding.

**Companion:** [Prompting 101](/academy/prompting-101)

### 5. Use products, ads, files, media, URLs, and Figma as AI context

**Recommended length:** 6 minutes

**Outcome:** know which source to attach for which job.

**Demo outline:**
1. Product = commerce truth.
2. Meta ad = campaign angle.
3. Media = real creative assets.
4. File/PDF = approved brief or copy.
5. URL = reference pattern.
6. Figma = approved design.
7. Selected section = editing scope.

**Companion:** [Prompting 101](/academy/prompting-101)

### 6. Fix an AI result without losing the parts you like

**Recommended length:** 5 minutes

**Outcome:** use KEEP / FIX ONLY / DO NOT CHANGE correction prompts.

**Demo outline:**
1. Start from a mostly correct hero.
2. Show one mobile crop issue.
3. Select the section.
4. Send a focused correction prompt.
5. Compare before/after.

**Companion:** [Prompt Library](/academy/prompt-library)

### 7. Recreate a section from a URL or screenshot

**Recommended length:** 7 minutes

**Outcome:** borrow structure while keeping Jurni brand/product truth.

**Demo outline:**
1. Show reference page.
2. Explain what is being borrowed.
3. Attach own product/assets.
4. Prompt the section.
5. Review interaction behavior.
6. Run a reference-contamination check.

**Companion:** [Reference → page](/academy/playbooks/recreate-reference-page)

### 8. Build from Figma

**Recommended length:** 7 minutes

**Outcome:** turn desktop/mobile frames into one responsive Jurni page.

**Demo outline:**
1. Attach desktop frame.
2. Attach mobile frame.
3. Explain that both represent one page.
4. Generate the sections.
5. Correct one section against Figma.
6. Verify a real CTA/product interaction.

**Companion:** [Figma → page](/academy/playbooks/figma-to-page)

## Learning path 4: CRO and experimentation

### 15. Review a page for CRO opportunities

**Recommended length:** 7 minutes

**Outcome:** diagnose customer decisions before creating variants.

**Demo outline:**
1. Provide traffic/audience context.
2. Run CRO review prompt.
3. Separate observation from proposed solution.
4. Pick one high-impact decision.
5. Write a hypothesis.

**Companion:** [CRO review](/academy/playbooks/cro-review)

### 16. Create a controlled experiment variant with AI

**Recommended length:** 6 minutes

**Outcome:** change one variable without accidentally redesigning the whole page.

**Demo outline:**
1. Duplicate control.
2. Paste hypothesis.
3. Use CHANGE ONLY / KEEP IDENTICAL prompt.
4. Compare variant with control.
5. Correct accidental differences.

**Companion:** [First A/B test](/academy/playbooks/first-ab-test)

### 17. Launch your first Jurni experiment

**Recommended length:** 7 minutes

**Outcome:** understand Smart Link → variants → traffic → results.

**Demo outline:**
1. Create experiment.
2. Choose new or existing Smart Link.
3. Add variants.
4. Set traffic weights.
5. Test the exact link.
6. Open results view.

**Companion:** [First A/B test](/academy/playbooks/first-ab-test)

### 18. Read an experiment without overclaiming

**Recommended length:** 7 minutes

**Outcome:** interpret primary and diagnostic metrics against the original hypothesis.

**Demo outline:**
1. Restate hypothesis and primary metric.
2. Review Sessions, Orders, Revenue and relevant rate metrics.
3. Explain lead versus conclusion.
4. Identify uncertainty/context.
5. Write a reusable learning.

**Companion:** [Optimization loop](/academy/playbooks/optimization-loop)

### 19. Decide what to test next

**Recommended length:** 6 minutes

**Outcome:** build a useful experiment backlog around customer decisions.

**Demo outline:**
1. Gather observations.
2. Map to customer decisions.
3. Generate hypotheses.
4. Rank by impact/evidence/clarity/reach/effort.
5. Pick one test.

**Companion:** [What to test](/academy/playbooks/what-to-test)

## Recording template

Use this reusable format for every Academy recording:

```text
1. Outcome (10–20 sec)
   “In this lesson, we'll…”

2. Context (20–40 sec)
   Show the campaign/product/problem.

3. Workflow demo
   Show only the steps needed for this outcome.

4. Why the key decisions matter
   Explain 2–3 important choices while making them.

5. Verify the result
   Show the page / live path / result—not just settings.

6. Next step (10–20 sec)
   Point to the companion playbook or next lesson.
```

## What not to put in Academy videos

Avoid:

- unreleased features shown as available to customers
- customer credentials or private data
- fake analytics or fabricated “winning” results
- giant feature tours
- deeply technical implementation details that belong in internal engineering documentation
- steps that are already obsolete in the current product

When the product changes, update the written workflow first and then replace recordings that show materially outdated controls.
