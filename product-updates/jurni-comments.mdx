Comments let your team leave feedback directly on an experience inside the Jurni editor. Each comment is attached to the part of the page being reviewed, which makes it easier to understand exactly what needs to change.

## When to use comments

Use comments when an experience is in review and you want to:

- request a copy or design change
- ask a question about a specific section
- leave implementation context for another editor
- keep feedback attached to the page instead of spreading it across Slack or screenshots

## Add a comment

<Steps>
  <Step title="Open the experience">
    Open the experience in the Jurni editor.
  </Step>
  <Step title="Enter Comment mode">
    Use the **Comment** control in the editor to switch from editing to commenting.
  </Step>
  <Step title="Select the part of the page">
    Click the section or element the feedback relates to. Jurni places the comment at that location so the context stays attached to the page.
  </Step>
  <Step title="Write the feedback">
    Add a specific, actionable comment and submit it.
  </Step>
  <Step title="Return to editing">
    Exit Comment mode when you are ready to continue editing the experience.
  </Step>
</Steps>

## Review existing comments

Comments can be reviewed from the editor's comment UI and sidebar. Threads stay associated with their page location so reviewers and editors can return to the exact area being discussed.

<Tip>
  Keep one requested change per comment. A comment such as **“Use the lifestyle image from the campaign creative here”** is much easier to action than **“This section feels off.”**
</Tip>

## Save edits before commenting

Jurni's editor includes a save check when switching into Comment mode. If you have unsaved page edits, save them first so the feedback is attached to the version your team is actually reviewing.

## Current limitations

Do not rely on features that are not visible in your workspace. In particular, older help-center material referenced future collaboration features such as shareable review links and teammate @mentions. Those should not be treated as available unless they are present in the current Jurni UI.
