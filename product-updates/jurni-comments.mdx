Use comments to keep feedback attached to the page content being discussed. A comment is a review thread, not a request that automatically edits or publishes the page.

For external reviewers, first use [Share and review links](/build/share-review-links). A public Preview Link is read-only and is not the same as the restricted comments workflow.

## Enter Comment mode

Select the **comments icon** in the editor header. In Comment mode, the page is used for feedback rather than normal editing; some editing panels are disabled.

If Jurni asks you to handle unsaved changes, read the action carefully:

| Current page state | What the prompt can offer |
| --- | --- |
| **Draft with unsaved edits** | Save the edits, discard them, or keep editing. |
| **Published experience with unsaved edits** | Publish the changes, discard them, or keep editing. |

<Warning>
  Choosing **Publish** before entering comments on a published experience can make pending changes live. Choose **Keep editing** when they are not ready. **Discard** intentionally removes those local edits; it is not a way to save them privately.
</Warning>

## Leave and follow up on feedback

<Steps>
  <Step title="Select the relevant content">
    In Comment mode, select the section or element you want to discuss and open the comment composer.
  </Step>
  <Step title="Write a specific comment">
    Describe the issue and expected result. Include the device view when relevant, such as “On mobile, the subscription label wraps over the price.”
  </Step>
  <Step title="Post and continue the thread">
    Submit the comment. Open its pin or its entry in the Comments sidebar to read the discussion and reply.
  </Step>
  <Step title="Resolve after verification">
    After making and checking the requested change, resolve the thread. Use the **Resolved** tab to find completed threads and reopen one when more work is needed.
  </Step>
</Steps>

The sidebar separates **Open** and **Resolved** comments. Select a thread to return to its target when that target still exists.

## Editing and deleting comments

Use the comment's available menu to edit or delete your own feedback. These actions change the discussion, not the page design. Resolve a completed discussion instead of deleting it when you want to keep the review history.

## When a pin no longer matches the page

A section or element can be replaced or removed after a comment is created. The thread can still appear in the sidebar even when it is no longer attached to a current target. Read the thread and confirm its context rather than assuming the original element still exists.

## When Comment mode is unavailable

Wait for an active AI operation to finish and leave a dedicated Global Section edit before entering comments. Also confirm that the reviewer has access to the restricted review link.

To resume design work, exit Comment mode and return to the editor. A reviewer asking for a change does not automatically gain editing access to the shop.
