Use a **Jurni experiment** when you want to send the same campaign audience to different page experiences and learn which approach performs better.

The basic model is:

**Campaign / ad → Smart Link → experiment → control or variant → cart / checkout**

The **Smart Link is the URL you put in the campaign**. The experiment decides which page that visitor receives.

## When should I run an experiment?

Good reasons to test:

- a clear page hypothesis, such as a different hero message;
- a dedicated Jurni landing page vs. your current website page;
- proof placed earlier vs. later;
- shorter vs. longer education;
- a different campaign-specific page structure;
- a meaningful offer presentation when the underlying commercial offer is the same.

A test is less useful when the team has no idea what changed or why.

**“New design vs old design”** can answer which whole page performed better, but it does not tell you which of 15 redesign decisions caused the difference.

For strategy, use [Create a controlled variation](/academy/playbooks/controlled-variation).

## The four parts of a Jurni experiment

### 1. Control

The current experience or existing page you want to compare against.

### 2. Variant

The alternative experience. Ideally, its difference from control maps to a clear hypothesis.

### 3. Smart Link

The campaign-facing entry URL. Traffic sent directly to a variant page does not automatically become experiment traffic.

### 4. Metric

The customer outcome you will use to guide the decision—such as CVR, RPS, AOV, or a relevant interaction rate.

Choose the primary metric **before** reading the result.

## Example: test a stronger hero

Hypothesis:

> We believe a benefit-led hero will improve purchase conversion for cold Meta visitors because the current feature-led headline does not explain why the product matters quickly enough.

Control:

- current hero.

Variant:

- benefit-led hero.

Keep fixed:

- product;
- offer;
- purchase options;
- CTA action;
- rest of page;
- campaign traffic.

Primary metric:

- CVR.

That is much easier to learn from than “AI made a better-looking page.”

## What URL should go in Meta / TikTok / email?

Use the **Smart Link connected to the experiment** when you want that campaign traffic assigned between variants.

Do **not** put the direct control or variant URL in the campaign and expect Jurni to split that traffic behind the scenes.

If you connect an existing Smart Link that already receives real traffic, starting the experiment can change where that existing traffic goes. Treat it as a live campaign decision.

## How traffic assignment works

For a standard weighted test, Jurni assigns traffic according to the configured variant weights.

A few things to expect:

- a 50/50 setup does not mean every consecutive pair of visitors splits perfectly one-and-one;
- a returning visitor can retain their assigned variant;
- repeatedly refreshing one browser is not a useful test of allocation;
- optional Routing Rules can deliberately send matching campaign parameters to a specific variant before the normal weighted split.

[How traffic assignment works →](/experiments/traffic-assignment)

## Experiments vs. page analytics

A Jurni experience can receive traffic **outside** an experiment—through a direct page URL, another campaign, preview / QA, or other path.

That means:

- experience-level sessions can include traffic that was never assigned by this experiment;
- experiment results should be read from the experiment context when making experiment decisions.

[Why experiment and experience sessions can differ →](/troubleshooting/experiment-experience-sessions)

## Testing against an existing website page

A variant can also point to a supported existing / external page when the tracking and attribution setup is correctly connected.

This lets you ask a useful business question:

> “Should this campaign use our current Shopify / website page or the new Jurni experience?”

Because the two destinations can use different runtimes, carts, scripts, or tracking paths, QA both carefully before interpreting the result.

[How to test against an existing page →](/experiments/testing-against-website)

For the marketer workflow, use [Jurni vs. existing page](/academy/playbooks/jurni-vs-existing).

## How should I read the result?

Start with:

1. the date range for the actual test period;
2. your primary metric;
3. the observed difference between variants;
4. supporting journey / revenue metrics;
5. any traffic, page, product, offer, or tracking changes that complicate interpretation.

Do not declare a winner simply because one number is temporarily higher.

[Read experiment results →](/experiments/reading-results)

Then use [Results → next test](/academy/playbooks/results-to-next-test) to turn the outcome into a learning and follow-up hypothesis.

## What happens when I pause or end a test?

Pause and End are traffic-routing decisions, not just reporting labels.

The current pause flow warns that traffic is sent to the shop home page. Ending asks you to choose the destination / winner that should continue receiving traffic.

Do not pause or end a live campaign without checking the exact routing consequence first.
