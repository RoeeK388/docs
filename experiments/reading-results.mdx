Jurni experiment reporting lets you compare the traffic, commerce, and revenue performance attributed to each variant. Use the same date range and the same decision metric when comparing variants.

## Current experiment metrics

The current experiment analytics model includes:

| Metric | How Jurni calculates it |
| --- | --- |
| **Sessions** | Attributed visits assigned to the experiment variant. |
| **Orders** | Orders attributed back to those visits. |
| **Revenue** | Attributed order revenue. |
| **CTR** | Visits with a click-through event ÷ sessions × 100. |
| **CVR** | Orders ÷ sessions × 100. |
| **Add-to-Cart Rate** | Visits with an add-to-cart event ÷ sessions × 100. |
| **Checkout Rate** | Visits with a checkout-initiated event ÷ sessions × 100. |
| **AOV** | Revenue ÷ orders. |
| **RPS** | Revenue ÷ sessions. |

Jurni counts the core interaction event groups at most once per visit for these rate calculations. This helps prevent repeated clicks or repeated add-to-cart actions in the same visit from inflating the visit-level rate.

## Choose the metric that matches the test goal

There is no single metric that is best for every experiment.

- Use **CVR** when the primary goal is increasing the percentage of visitors who purchase.
- Use **RPS** when you want to compare the amount of revenue produced per visit.
- Use **AOV** when the hypothesis is specifically about basket size.
- Use **CTR, Add-to-Cart Rate, or Checkout Rate** when the experiment is intended to improve an earlier step in the shopper journey.

<Tip>
  Define the primary metric before the experiment starts. Looking for whichever metric improved after the test makes the result much easier to over-interpret.
</Tip>

## Date ranges matter

Experiment metrics are scoped to the selected reporting period. When you compare an experiment with the underlying Experience analytics, make sure both views are using the same time window.

An Experience view can include traffic that did not enter through the experiment. For example, someone may visit the page directly or an ad may use the page URL instead of the experiment Smart Link. That traffic can appear in Experience analytics without belonging to an experiment variant.

## Traffic changes are not retroactive

If you change variant weights or routing rules after an experiment has started, historical traffic stays attributed to the variant it originally reached. New routing settings affect future visitors; they do not rewrite earlier results.

<Warning>
  Changing traffic allocation or routing logic during a test can make the combined result harder to interpret. Record when and why the change was made so you can evaluate the appropriate date range.
</Warning>

## Statistical significance

Jurni does **not currently expose the new statistical-significance/confidence experience as a shipped part of experiment reporting**. Confidence, lift, p-value, and winner-state calculations are being developed separately from the current performance metrics.

Until that feature is released, do not interpret the current dashboard as automatically declaring a statistically significant winner. Use adequate sample size, a pre-defined decision metric, and a test duration that captures normal traffic variation before making a decision.

## Custom downstream events

Jurni can support mapped downstream events for specific implementations, but custom events are not yet presented as standard variant-level metrics throughout the experiment graphs and variant breakdown. If your test depends on a custom event such as quiz start, email capture, or another downstream conversion, confirm how that event will be measured before launching the test.

## Troubleshooting differences

If the experiment numbers do not match another view, check these first:

1. The date range in both reports.
2. Whether all campaign traffic is using the intended Smart Link.
3. Whether the underlying Experience also receives direct traffic.
4. Whether the compared platform uses the same session and attribution model.
5. Whether consent or tracking configuration prevented an event from being recorded.
