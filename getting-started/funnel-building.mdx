Building in Jurni is a workflow: choose the source and goal, create the page structure, connect real commerce behavior, then QA and publish the result.

## Choose how to start

You can begin from:

- AI generation
- A Jurni template
- A blank page
- A Figma design
- An existing page or experience you want to replicate or iterate on

Choose the fastest starting point that already contains the structure you need. Do not rebuild a complex Buy Box from scratch if an approved reusable section already exists.

## Think in sections

A Jurni page is made from sections that each have one main job.

A typical paid landing page might include:

1. Announcement / navigation
2. Hero
3. Product or Buy Box
4. Benefits / problem-solution
5. Proof or reviews
6. Product details / ingredients
7. FAQ
8. Repeated purchase CTA
9. Footer

Not every page needs every section. Build around the shopper's decision rather than filling a template for the sake of length.

## Start with campaign intent

Before building, define:

- Traffic source
- Audience / persona
- Ad angle
- Product or offer
- Primary shopper action
- Whether the page is meant to sell directly, educate, quiz, bundle, or route elsewhere

This context should shape the page more than a generic CRO checklist.

## Add real commerce early

Connect the actual Shopify product before the page is considered complete.

Configure and test:

- Product and variants
- Purchase options
- One-time/subscription
- Selling plans
- Quantity
- Bundle behavior
- Gift with purchase
- Discounts
- Cart / checkout action

Designing the page around fake product controls and adding commerce at the very end usually creates avoidable rework.

## Reuse approved patterns

Use Saved/Global Sections for approved headers, Buy Boxes, offer modules, or other complex sections. Reuse saves time, but always verify product and market-specific configuration after inserting the section.

## Build desktop and mobile together

Do not treat mobile as a final cleanup pass. Review each important section on both breakpoints while building.

Pay particular attention to:

- Hero crop
- Buy Box stacking
- Variant selectors
- Carousels
- Sticky CTAs
- Long subscription labels
- Modal behavior

## Finish with QA and publishing

Before launch:

1. Run the QA Checklist.
2. Test the real cart/checkout flow.
3. Verify tracking.
4. Choose the publishing method.
5. Confirm the live URL.
6. If using paid traffic, test the Smart Link or experiment entry path.
