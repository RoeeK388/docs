Use **Settings → Integrations → Data Integrations** to configure the browser-side tracking tools Jurni currently supports for Jurni-hosted pages.

<Warning>
  A native **Shopify Page** runs inside the Shopify theme environment. If the same pixel or GTM container is already installed by the Shopify theme/app stack, do not add a second copy through Jurni without a specific reason. Duplicate installations can double-fire events.
</Warning>

## Current Data Integration fields

Jurni currently exposes the following tracking configuration:

| Integration | Value Jurni asks for |
| --- | --- |
| Meta Pixel | One or more Meta Pixel IDs |
| Google Tag Manager | Container ID in `GTM-...` format |
| Google Analytics | GA tag / Measurement ID in `G-...` format |
| TikTok | TikTok Pixel ID |
| Blotout | Full **EdgeTag URL** |
| Axon | Axon Pixel ID |
| Northbeam | Northbeam Pixel ID |
| Polar Analytics | Shopify domain in `store.myshopify.com` format |
| Triple Whale | Enable/disable integration toggle |
| Shopify Analytics | Separate public Storefront API token setup |

Jurni validates some field formats before saving—for example GTM IDs must start with `GTM-`, GA IDs with `G-`, Northbeam expects a valid identifier, and Polar expects a `.myshopify.com` shop URL.

## Add or update tracking

<Steps>
  <Step title="Open Settings → Integrations">
    Go to **Data Integrations → Tracking Pixels**.
  </Step>
  <Step title="Enter the provider values">
    Add only the integrations your measurement stack actually uses. Jurni supports multiple Meta Pixel IDs when the shop intentionally needs more than one.
  </Step>
  <Step title="Save Changes">
    Save the tracking configuration after the values pass Jurni's validation.
  </Step>
  <Step title="Test a live page">
    Open a published Jurni URL and validate the provider with its browser/debug tool. For GTM, use Tag Assistant; for Meta, use Events Manager/Pixel Helper or your existing debugging workflow.
  </Step>
</Steps>

## Jurni-hosted pages vs. Shopify Pages

For a page served through Jurni's app-proxy/custom-subdomain storefront, the Jurni data-integration configuration is the normal place to load supported tracking.

For a **Shopify Page**, the merchant's Shopify theme may already load Meta, GTM, GA4, consent tooling, or other scripts. Use the existing Shopify installation when appropriate instead of blindly adding the same tracker through both environments.

This distinction is one of the most common causes of duplicate reporting.

## Consent can change what fires

A correctly configured pixel can still be absent if the shopper has not granted the permission required by Shopify or the consent manager in use.

When debugging:

1. test both consented and non-consented states
2. confirm the provider script actually loads
3. confirm the Jurni shopper action occurs
4. verify the downstream event is sent once

## GTM needs an event bridge for Jurni browser events

Saving a GTM container ID loads GTM on supported Jurni-hosted pages. If you also want Jurni interactions such as completed add to cart or checkout actions to become GTM Custom Events, configure the Jurni-to-GTM event bridge described in the **Google Tag Manager** guide.

## Custom providers

If a provider is not available as a native Data Integration, use **Custom Scripts** when the vendor can safely run as a browser script. Custom Scripts support page targeting and a Tracking mode that keeps tracking scripts out of editor Preview.

Do not place private/server-side credentials in Custom Scripts.
