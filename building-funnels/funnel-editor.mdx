The **Experience Editor** is where you build and refine a Jurni page. Use it to manage sections, content, media, responsive behavior, product interactions, and the actions shoppers take from the page.

## Open the editor

Open an experience from the **Experiences** area in Jurni. The editor loads the current working version of the page so you can make changes before publishing them to shoppers.

## Main parts of the editor

<CardGroup cols={3}>
  <Card title="Page canvas" icon="desktop">
    Shows the page as you build it. Select sections and elements directly from the canvas and switch between desktop and mobile views while editing.
  </Card>

  <Card title="Sections" icon="layer-group">
    Controls the structure of the page. Add sections from the Section Library, select existing sections, reorder them, or reuse Saved/Global Sections.
  </Card>

  <Card title="Editing controls" icon="sliders">
    The available controls depend on what you select. Use them for content, media, layout, actions, and section-specific configuration.
  </Card>

Jurni also exposes AI chat inside the editing workflow for changes that are easier to describe than configure manually.

## Work section by section

A section should have a clear job in the shopper journey. Common jobs include:

- hero / campaign hook
- product education
- social proof
- comparison or ingredients
- Buy Box / purchase decision
- FAQ
- repeated CTA

Use the **Section Library** to add new patterns and **Saved/Global Sections** when your shop already has an approved section you want to reuse.

## Edit content and media

Select the relevant content in the editor to update copy, images, video, links, or section configuration.

For images, Jurni also supports image repositioning/crop controls so you can change the visible focal point without replacing the underlying asset.

For larger design changes, AI chat can modify or rebuild a section based on your instruction. Review AI changes visually and functionally rather than assuming a successful generation means the section is launch-ready.

## Configure shopper actions carefully

Buttons and purchase controls can do very different things. Depending on the section, an action may:

- scroll to another section
- add a product to cart
- open cart
- continue to checkout
- navigate to another product/page
- open an external URL

The visual label on a CTA does not determine its behavior. Test the configured action itself before publishing.

## Products and Buy Boxes

Product configuration should be handled as real commerce behavior, not placeholder design.

For any shoppable section, confirm:

- Shopify product and variant
- one-time vs. subscription purchase option
- selling plan
- quantity
- bundle rules, when used
- discount/offer behavior
- post-add-to-cart action

Use the dedicated **Products & Buy Boxes** docs for those behaviors.

## Desktop and mobile

Review both breakpoints throughout the build. Pay particular attention to:

- image crop
- section spacing
- Buy Box stacking
- carousels
- long labels
- sticky CTAs
- modals and overlays

Do not wait until the final QA pass to discover that a desktop-first section does not work on mobile.

## Preview vs. live page

Editor Preview is useful for layout and interactions, but it is not identical to every published environment.

In particular:

- tracking Custom Scripts can be intentionally excluded from Preview
- Shopify Pages run inside the Shopify theme environment
- third-party widgets may behave differently on a live URL

Always test the final publishing destination before sending meaningful traffic.

## Before publishing

Use the QA Checklist to verify the page, products, tracking, mobile behavior, and live cart/checkout path. Then choose the appropriate publishing method: Jurni URL/custom subdomain, Smart Link traffic routing, or native Shopify Pages where supported.
