3. **Did my experiment create a meaningful difference worth acting on?**

## Experience analytics vs. experiment results

This distinction matters a lot.

**Experience analytics** can include traffic that reaches the page from multiple paths:

- Smart Links;
- experiments;
- direct page URLs;
- other campaigns;
- QA / internal visits.

**Experiment analytics** focuses on the visits assigned through that experiment.

So if your experiment says 5,000 sessions but the underlying page shows 6,200, that is not automatically a tracking bug. The page may simply receive traffic outside the experiment.

## The core commerce metrics

| Metric | The marketer question it answers |
| --- | --- |
| **Sessions** | How many attributed visits reached the experience / variant? |
| **Orders** | How many attributed purchases came from those visits? |
| **Revenue** | How much attributed order revenue did they generate? |
| **CVR** | What percentage of sessions produced an order? |
| **RPS** | How much attributed revenue did each session produce on average? |
| **AOV** | How large was the average attributed order? |
| **CTR** | How often did sessions include the relevant click-through action? |
| **Add-to-Cart Rate** | How often did sessions reach Add to Cart? |
| **Checkout Rate** | How often did sessions start checkout? |

Use the [Metrics Glossary](/data-dictionary/metrics-glossary) for exact current definitions / formulas.

## Read the journey, not only CVR

When performance moves, the earlier steps can help you understand **where** to investigate.

A useful simplified journey is:

**Session → Click / product interaction → Add to Cart → Checkout → Order**

Examples:

### Add-to-Cart Rate is weak

Investigate:

- message / product mismatch;
- unclear offer;
- purchase choices;
- product / price expectation;
- CTA / Buy Box usability;
- mobile layout.

That does not prove which issue is responsible. It tells you where to look.

### Add to Cart looks healthy, Checkout Rate is weak

Investigate:

- cart behavior;
- gift / discount expectations;
- unexpected quantity / plan;
- theme / third-party cart issues;
- shopper hesitation before checkout.

### Checkout Rate looks healthy, orders are weak

Investigate the downstream checkout:

- shipping / taxes;
- payment;
- discount / offer mismatch;
- checkout errors;
- attribution / purchase tracking.

Landing-page changes are not always the right fix for a downstream problem.

## Use date ranges deliberately

Before comparing two reports, align the time period.

Ask:

- Did the campaign start / stop during this range?
- Did the page change materially?
- Did an offer change?
- Did experiment weights / routing change?
- Was tracking fixed partway through?
- Does the other platform use a different timezone?

A wider range is not always “more accurate” if it mixes fundamentally different campaign periods.

## Compare pages responsibly

A page with higher CVR is not automatically “better” if:

- it receives warmer traffic;
- it has a stronger offer;
- it sells a lower-priced product;
- it has different purchase options;
- its campaign mix is different.

If you want to compare two page ideas fairly under the same campaign traffic, use a [Jurni experiment](/experiments/what-are-experiments).

## Compare Jurni with GA4, Meta, Shopify, Northbeam, etc.

Different systems can legitimately report different totals because they use different:

- session definitions;
- identity / cookie logic;
- attribution windows;
- traffic scope;
- consent behavior;
- event delivery paths;
- purchase attribution rules.

Before asking “which number is right?”, ask whether the systems are answering the same question.

Examples:

- Meta ad-account revenue is not the same scope as all Jurni-attributed page revenue.
- Shopify total orders include store traffic unrelated to the Jurni campaign.
- GA4 can define sessions differently from Jurni.
- a Jurni page can receive direct traffic outside the experiment you are analyzing.

## A marketer workflow for reviewing a campaign

<Steps>
  <Step title="Start with the campaign question">
    Are you reviewing one page, an A/B test, or the ad account? Open the report that matches that question.
  </Step>
  <Step title="Set the relevant period">
    Match the actual campaign / test window.
  </Step>
  <Step title="Read the primary business outcome">
    Start with CVR / RPS / revenue / the metric your campaign is actually trying to improve.
  </Step>
  <Step title="Use earlier journey metrics as diagnostics">
    Identify where behavior appears to change, then investigate the page / cart / checkout rather than jumping straight to a design fix.
  </Step>
  <Step title="Form one useful hypothesis">
    Convert the observation into something testable rather than a list of random CRO changes.
  </Step>
</Steps>

For that last step, use [CRO audit → first edit](/academy/playbooks/cro-audit) or [Results → next test](/academy/playbooks/results-to-next-test).

## Useful analytics questions

**“Which page should I scale?”**

First make sure the pages have comparable audience / offer context. For a controlled answer, run an experiment.

**“Why did CVR fall?”**

Look at earlier journey metrics, campaign / offer changes, and checkout before assuming the hero is responsible.

**“Why are experiment sessions lower than page sessions?”**

The page can receive non-experiment traffic. See [experiment vs experience sessions](/troubleshooting/experiment-experience-sessions).

**“Can I use Jurni data to understand Meta performance?”**

Use Jurni page / experiment reporting for the landing experience, and [Meta ad insights](/analytics-reporting/meta-ad-insights) for the connected ad account view.
